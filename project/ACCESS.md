# สิทธิ์การใช้งาน VING Warroom

กำหนดตามเจ้าของเว็บวันที่ 23 กันยายน 2569

| ตำแหน่ง | อ่านข้อมูล | เพิ่ม / แก้ไข / ลบ | อนุมัติ / ไม่อนุมัติ |
| --- | --- | --- | --- |
| CEO / Trade Manager | ได้ | ได้ทุกส่วนที่เว็บรองรับ | ได้ |
| บุคคลทั่วไป | ได้ | ไม่ได้ | ไม่ได้ |
| Assistant Trade Manager | ได้ | ได้ทุกส่วนที่เว็บรองรับ | ไม่ได้ |
| Business Development | ได้ | ได้ทุกส่วนที่เว็บรองรับ | ไม่ได้ |

ตั้งแต่ 27 กันยายน 2569 บัญชีผู้ช่วยเดิมทั้งสามอยู่ใน “ทีมห้าง” และคงตำแหน่ง Assistant Trade Manager บัญชี Business Development แยกรหัสผู้ใช้เป็น `business-development-1` ใช้ `BUSINESS_DEVELOPMENT_PASSWORD` ใน Sites secrets และใช้ตำแหน่งเป็นชื่อแสดงจนกว่าเจ้าของจะระบุชื่อผู้ใช้ มีสิทธิ์ `assistant` เช่นเดียวกับทีมห้าง จึงส่งงานได้แต่ตัดสินอนุมัติไม่ได้ ร่างงานและสถานะอ่านแจ้งเตือนแยกตามบัญชี

รหัสผู้บริหารใช้ `ADMIN_PASSWORD`, ผู้ชมใช้ `VIEWER_PASSWORD` และผู้ช่วยทั้งสามชุดใช้ `ASSISTANT_PASSWORD_1`, `ASSISTANT_PASSWORD_2`, `ASSISTANT_PASSWORD_3` ตามลำดับที่เจ้าของระบุ เก็บค่าจริงเป็น Sites secrets เท่านั้น ไม่ใส่รหัสในเอกสาร ซอร์สโค้ด หรือข้อมูลส่งให้เบราว์เซอร์

เซิร์ฟเวอร์เป็นผู้ตรวจสิทธิ์ทุกคำขอ บทบาท `assistant` มี `canEdit=true` และ `canApprove=false` การตัดสินทั้ง Trade / CEO และการอนุมัติแจ้งเตือนจำกัดให้ `admin` เท่านั้น ผู้ช่วยอ่านรายการรออนุมัติได้ การแก้ไขข้อเสนอจะล้างผลอนุมัติเดิมและกลับไปรออนุมัติ ไม่ยอมรับสถานะอนุมัติที่แนบมากับคำขอสร้างหรือแก้ไข

การอ่าน/ซ่อนแจ้งเตือนเป็นสถานะของแต่ละเบราว์เซอร์ ไม่แก้ไขข้อมูลต้นฉบับหรือผลอนุมัติ ระบบนำเข้าข้อมูลอัตโนมัติยังใช้ service token แยกจากรหัสเข้าเว็บ

ใช้ session รุ่น `v4` ที่ลงลายเซ็นทั้งบทบาทและรหัสผู้ใช้ เพื่อให้ session รุ่นก่อนการตั้งสิทธิ์ครั้งนี้หมดสิทธิ์ ผู้ใช้งานเดิมต้องเข้าสู่ระบบใหม่

ตรวจหลัง build ด้วย `node --test role-permissions.test.mjs event-permissions.test.mjs notifications.test.mjs contracts-storage.test.mjs event-request-edit.test.mjs event-proposals.test.mjs event-review.test.mjs event-proposal-deletions.test.mjs` และ `node realtime.test.mjs`

ชื่อผู้ใช้ของผู้ช่วยแต่ละรหัสอ่านจาก `ASSISTANT_NAME_1`, `ASSISTANT_NAME_2`, `ASSISTANT_NAME_3` ใน Sites secrets ตามลำดับเดียวกับรหัสผ่าน แสดงชื่อบนบัญชี รายการเสนอ Event รายละเอียดคำขอ และการแจ้งเตือนขออนุมัติ ชื่อผู้ส่งบันทึกจาก session ฝั่งเซิร์ฟเวอร์เท่านั้น ไม่เชื่อชื่อหรือรหัสผู้ใช้ที่แนบมากับแบบฟอร์ม

คำขอเก็บ `submittedBy` เป็นผู้ส่งคำขอรอบล่าสุด และ `createdBy` เป็นผู้เสนอครั้งแรก การแก้ไขส่งใหม่เปลี่ยนเฉพาะชื่อผู้ส่งรอบล่าสุด ประวัติและชื่อที่บันทึกไว้ไม่เปลี่ยนตามการตั้งชื่อบัญชีภายหลัง ครอบคลุม Event สัญญา และแจ้งลบข้อเสนอ รายการเก่าที่ไม่มีชื่อแสดง “ไม่ได้บันทึกชื่อ” โดยไม่เติมข้อมูลย้อนหลังจากการคาดเดา
