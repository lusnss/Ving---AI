# ทำงาน VING บนคลาวด์

ต้นฉบับเว็บจริงอยู่ใน source repository ของ Site เดิม ส่วน GitHub Private เป็นสำเนาโค้ดสำหรับพัฒนาบนคลาวด์และเก็บประวัติ งานเก่าหลายเวอร์ชันเก็บแยกจากโค้ดที่ใช้จริงเพื่อไม่ให้เขียนทับกัน

## การแก้เว็บครั้งต่อไป

เปิด Site เดิมจาก ChatGPT บนเว็บแล้วเลือกแก้ไข หรือใช้ Codex Cloud ที่เชื่อม repository นี้ เริ่มจากต้นฉบับเวอร์ชันล่าสุด ตรวจ build แล้วเผยแพร่กลับ Site เดิมตาม Sites hosting workflow อย่าใช้โฟลเดอร์ Mac เป็นแหล่งหลัก การ push GitHub อย่างเดียวไม่เท่ากับเผยแพร่เว็บ

## ข้อมูลที่ใช้งาน

- Event, สัญญา, กิจกรรม, โปรโมชั่น, ร่างงาน และข้อมูลการจัดคนใช้ฐานข้อมูล D1 ของเว็บ
- ไฟล์ รูป และข้อมูลจากการเชื่อมต้นทางใช้ R2 ของเว็บ
- Events และสัญญาอ่าน Google Sheets จากเซิร์ฟเวอร์เมื่อมีผู้ใช้งานอ่านข้อมูล โดยใช้ข้อมูลที่เก็บไว้ไม่เกิน 60 วินาทีก่อนอ่านต้นทางใหม่ ถ้าต้นทางล้มเหลวจะคงข้อมูลและเวลาที่อ่านสำเร็จครั้งก่อน ไม่ต้องเปิด Mac แต่ไม่ใช่งานตามเวลาขณะที่ไม่มีผู้ใช้งาน
- การเชื่อม Scaleup, Odoo และบริการสต็อกใช้ฝั่งเซิร์ฟเวอร์
- Microsoft Excel ต้องเชื่อมบัญชีและทดสอบข้อมูลจริงตาม `automation/MICROSOFT-ONLINE-SETUP.md` ก่อนเลิกใช้ตัวนำเข้าบน Mac
- งาน AI, Scout และการสร้างสื่อของระบบเดิมยังต้องมี cloud worker และสิทธิ์บริการที่ใช้งานได้ การย้ายคิวงานเพียงอย่างเดียวไม่ใช่การเปิด worker

## ก่อนปิดระบบเดิม

นำเข้าชุดข้อมูล workspace เดิม 16 ตาราง รวม 14 รายการขึ้น R2 แล้วเมื่อ 3 ตุลาคม 2026 ตรวจ hash และจำนวนจากข้อมูลที่อ่านคืนครบทุกตาราง ช่องทางนำเข้า HTTP ชั่วคราวถูกปลดออกหลังการตรวจ และการแก้ต่อผ่าน API ที่ต้องเข้าสู่ระบบจะบันทึกบนคลาวด์ จำนวนนี้ไม่รวมข้อมูลธุรกิจเดิมใน D1/R2 และไม่หมายความว่าไฟล์ย้อนหลังทั้งโฟลเดอร์ถูกสำรองครบแล้ว

ต้องตรวจการนำเข้าข้อมูลครบ, เขียนและอ่านคืนจากคลาวด์ได้, งานอัปเดตทำงานเมื่อ Mac ปิด และกู้คืนจากสำเนาได้ จากนั้นจึงหยุดงานซิงก์เดิม ห้ามลบโฟลเดอร์ต้นทางก่อนผ่านการตรวจเหล่านี้

ไฟล์รหัสเชื่อมต่อไม่อยู่ในชุดโค้ดทั่วไป ให้ใช้ secret settings ของบริการแต่ละแห่ง เอกสารและไฟล์งานเก็บเป็น Private และไม่เปลี่ยนสิทธิ์ผู้เข้าถึงเอง
