# เชื่อมสต็อกสาขาเข้า VING Warroom

แท็บ `/branch-stock` ใช้ API `/api/branch-stock` หลังเข้าสู่ระบบ Warroom ตามสิทธิ์เดิม ผู้ชมและผู้ดูแลอ่านข้อมูลได้ ไม่มีการแก้ไขสต็อก

## การยืนยันตัวตนต้นทาง

- ใช้บัญชีที่เจ้าของอนุญาต เก็บเฉพาะใน secret `BRANCH_STOCK_ACCOUNT_EMAIL` ของ Sites ไม่บันทึกอีเมลใน source หรือส่งให้เบราว์เซอร์
- ก่อนอ่านแต่ละครั้ง เซิร์ฟเวอร์เรียก `POST https://ving-branch-stock.vercel.app/api/auth/login` ตามขั้นตอนหน้าเว็บต้นทาง หากต้องเลือกสาขา จะเลือกสาขาแรกจากรายการที่ต้นทางอนุญาตและเข้าสู่ระบบอีกครั้ง
- ตรวจว่าบัญชีที่ตอบกลับตรงกับบัญชีที่กำหนดและมี role `admin`, `admin_editor` หรือ `admin_viewer` แล้วจึงใช้ `x-actor-email` อ่าน `GET /api/admin/stock-dashboard` ตามวิธีของหน้า Dashboard ต้นทาง
- การเลือกสาขาตอนเข้าสู่ระบบไม่จำกัดตัวกรอง Dashboard; เมื่อไม่ส่ง `branchIds` Dashboard อ่านรวมทุกสาขาตามที่ API อนุญาต
- หากต้นทางเปลี่ยนขั้นตอนยืนยันตัวตนหรือเพิกถอนสิทธิ์ ระบบแสดงข้อผิดพลาดและไม่ข้ามการตรวจสิทธิ์
- ทางเลือก: ตั้ง secret `BRANCH_STOCK_API_TOKEN` จากผู้ดูแลต้นทาง ระบบจะใช้ `x-admin-token` แทนบัญชี หากตั้งทั้งสองค่า token มีลำดับก่อน

## ข้อมูลและการอัปเดต

ดึงเมื่อเปิดแท็บ เปลี่ยนสาขา ค้นหา SKU หรือกดอัปเดตข้อมูล ไม่มีงานเบื้องหลังตามเวลา รองรับพารามิเตอร์ `branchIds` และ `q` ข้อมูลส่งกลับเบราว์เซอร์จำกัดเฉพาะรหัส/ชื่อสาขา สถานะซิงก์ SKU บาร์โค้ด รุ่น สี ไซซ์ ยอดปกติ/On-Hold/รวม จำนวนสาขา และเวลาอัปเดต ไม่ส่ง response ต้นทางทั้งหมดหรือรายละเอียดบัญชี

## การตรวจสอบ

ทดสอบเข้าสู่ระบบผ่านหน้าเว็บปกติและอ่าน Dashboard จริงสำเร็จ วันที่ 22 กันยายน 2026 UTC พบ 51 สาขาและ 1,379 SKU ในการตรวจครั้งนั้น จำนวนอาจเปลี่ยนตามต้นทาง ตรวจ adapter และตัวกรองซ้ำด้วยข้อมูลต้นทางก่อนเผยแพร่

Tests: `node branch-stock.test.mjs` หลัง `node build.mjs`
